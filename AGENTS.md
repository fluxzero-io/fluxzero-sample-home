## Fluxzero Home

Read `README.md` and the relevant product documents in `docs/` before changing the domain. Keep this application on published SDK `2.0.0-rc.13` unless the user requests an upgrade. Maven resolves it from Fluxzero Packages; no SDK checkout or local candidate build is required. Use the work backlog in `../work-backlog` for plans and qualification notes.

Select the exact project version through `docs_start`. For rc.13 the documentation source commit is `d0909e09696c58cfb04cc1146dd7f864b3c54ca6`; the plugin resolves the published archive without a local archive override.

Preserve independent Model lifecycles and the boundary between desired settings and reported device state. Scenes and their constituent commands must remain one atomic Model commit. RunRoutine and ReactToHome explicitly orchestrate assertAndApply: scene and successful progress commit together; functional refusal rolls back before a separate pause command, while technical failures propagate. Do not reintroduce a preflight scene execution or assume the pause is part of the failed transaction. Scheduling effects follow committed intent and reconcile from current state. Device brands, credentials and physical delivery belong to concrete integration adapters. The first Home Assistant adapter lives in `homeassistant`; read `docs/home-assistant.md` before changing it. Keep physical I/O after domain commit, credentials outside domain commands and Models, complete observations separate from service acknowledgements, and supported API capabilities explicit. Represent each external interaction as a command or query with its webrequest in its own handler; invoke it through Fluxzero rather than injecting an API service. The Home Assistant interactions use tracked self-handlers in the home-assistant-api consumer. Share only endpoint configuration and request/response conventions where useful. Use the ordinary Fluxzero WebRequestGateway for outbound HTTP and TestFixture HTTP handlers for remote responses; test via whenCommand/whenQuery, without API beans or withBean. The adapter puts its bearer token in the standard Authorization header; Auditlog masks standard credentials in visible records and downloads. The configured Home Assistant URL must be reachable from the forward proxy. Do not add public control endpoints without household-scoped authentication and authorization.

The existing home-scoped queries use component documents from explicit relationship paths. Keep Models on plain `@Model`; justify additional persistence against an actual query or authoritative load requirement. `DeviceStatus` requires event sourcing for event-bound before/after readings; do not add a duplicate previous-reading field. `RunRoutine` declares its Routine as `@Parent`; the SDK cancels stored work on direct or cascade deletion. Routine schedule reconciliation uses one tracker for current status/deadline changes and does not cancel absent routines. Retain generation/deadline/current-state guards for delivered work. See `docs/sdk-2.md` for this application's choices and the versioned SDK query guide for the full contract.

Use `feature/`, `fix/`, `docs/` or `chore/` branch names; never use `codex/`. Use Conventional Commits. Commit messages describe intent and behavioral impact, without test commands or results. Do not commit generated build outputs or `.fluxzero/dev/`, and do not push without a request.

Use domain-specific details values for descriptive input and preserve focused command intent. This example app has not been deployed and uses the current schema without upcasters or explicit serialization revisions. Use a fresh temporary runtime for incompatible local example data. Add schema migrations only when there is actual historical data to preserve or the user explicitly requests a migration example. Keep routine generations and deadlines for rescheduling. Automations recognize event-bound before/after changes without source-revision bookkeeping, exact-current-revision guards or replacement deduplication state. Execution recovery belongs to the SDK and Runtime; their planned durable-execution contract is not yet a guarantee of the pinned SDK release. Do not add application tests that requalify generic runtime redelivery guarantees. Keep execution history in events rather than duplicate counters or timestamps. Automation.effectiveFrom bounds its current definition; cooldownEndsAt is its operational quiet-period deadline. Avoid scanning history for each sensor signal.

Put model-independent input constraints on command/value fields or no-argument `@AssertTrue` methods, cascading with `@Valid`. Fluxzero evaluates field constraints before method constraints; do not repeat null checks in those methods for values already covered by `@NotNull`, including constrained collection elements. Keep checks that express optional or conditionally required domain input. Do not load or inject a Model merely to check names, required values, numeric ranges or combinations of supplied fields. Keep state/relationship rules in `@AssertLegal`. Rely on Fluxzero's collection deserialization defaults; do not add constructors merely to normalize null collections or defensively copy command input.
